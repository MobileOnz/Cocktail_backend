# 보안 인증/인가 개선 기록

**작업 일자**: 2026-04-17
**대상 영역**: Spring Security, JWT Filter, Social Login, 테스트용 인증 API
**검증 명령**: `./gradlew test`

---

## 요약

이번 작업은 V2 API 접근 제어와 인증 토큰 처리 방식을 개선해, 개발/테스트용 인증 기능이 운영 환경에서 노출될 가능성을 줄이고 공개 API와 인증 필요 API의 경계를 명확히 한 작업이다.

핵심 변경은 다음과 같다.

- V2 API 전체 허용 정책 제거
- 공개 API allowlist 도입
- 테스트용 JWT 발급 API의 운영 프로필 비활성화
- 공개 API에서 잘못된 JWT가 붙어도 익명 요청으로 처리되도록 보완
- SDK 기반 소셜 로그인 API가 기존처럼 인증 없이 동작하는지 테스트 추가
- 민감 토큰 평문 로그 제거

---

## 발견된 문제

## 1. V2 API가 기본 공개되는 구조

기존 설정은 V2 API 전체를 허용하고, JWT 필터 내부의 경로 목록으로 일부 API만 보호하는 구조였다.

이 구조에서는 신규 API가 추가될 때 보호 목록에 누락되면 인증 없이 접근 가능한 API가 생길 수 있다.

### 영향

- 회원 API, 검색 기록, 북마크, 반응 API 같은 사용자별 기능이 설정 누락 시 공개될 수 있음
- 보안 정책이 `SecurityConfig`와 `JWTFilter`로 분산되어 변경 실수 가능성이 큼
- 테스트용 인증 기능과 결합될 경우 인증 우회 위험이 커짐

---

## 2. 테스트용 JWT 발급 API의 운영 노출 가능성

개발/테스트용 JWT 발급 컨트롤러가 운영 소스 경로에 존재했다.

### 영향

- 운영 프로필에서 Bean으로 등록될 경우, 개발 편의를 위한 인증 기능이 외부에 노출될 수 있음
- 인증 체계의 신뢰 경계가 약화됨

---

## 3. 공개 API에 잘못된 Authorization 헤더가 붙으면 실패할 수 있는 문제

모바일 앱은 공통 HTTP 클라이언트에서 `Authorization` 헤더를 자동으로 붙이는 경우가 많다.
이때 공개 API 호출에도 만료되었거나 잘못된 토큰이 함께 전달될 수 있다.

기존 개선안만으로는 일부 공개 API가 이 잘못된 토큰 때문에 실패할 수 있었다.

### 영향

- 비로그인도 접근해야 하는 칵테일 조회 API가 실패할 수 있음
- 비로그인 사용자 추적용 모니터링 API가 실패할 수 있음
- SDK 기반 소셜 로그인 API가 잘못된 기존 토큰 때문에 막힐 수 있음

---

## 4. 토큰 평문 로그 출력

OAuth access token, JWT access token, refresh token이 로그에 직접 남을 수 있는 코드가 있었다.

### 영향

- 로그 접근 권한만으로 사용자 세션 탈취 위험 발생
- 장애 분석/로그 수집 과정에서 민감정보가 2차 확산될 수 있음

---

## 해결 내용

## 1. V2 API 접근 제어를 allowlist 방식으로 변경

기존의 V2 전체 허용을 제거하고, 공개 API만 명시적으로 허용하도록 변경했다.

### 변경 전

- `/api/v2/**` 전체 허용
- `/onz/api/v2/**` 전체 허용

### 변경 후

- 공개 API만 `PUBLIC_V2_URLS`에 명시
- 나머지 `/api/v2/**`, `/onz/api/v2/**`는 기본 인증 필요

### 수치

- 광범위 wildcard 허용 규칙 2개 제거
- 공개 API 경로 48개를 명시적 allowlist로 관리
  - 일반 경로 24개
  - `/onz` prefix 경로 24개

---

## 2. 테스트용 JWT 발급 API 프로필 제한

테스트용 인증 컨트롤러에 프로필 제한을 추가했다.

```java
@Profile({"local", "dev", "test"})
```

운영 프로필에서는 해당 Bean이 등록되지 않는다.

---

## 3. JWT 필터 처리 방식 보완

공개 API는 다음 정책으로 처리되도록 변경했다.

- 토큰이 없으면 익명 요청으로 통과
- 토큰이 유효하면 `SecurityContext` 설정
- 토큰이 잘못되었거나 만료되었으면 익명 요청으로 통과

인증 필요 API는 다음 정책을 유지한다.

- 유효한 JWT가 없으면 실패
- 만료/블랙리스트 토큰이면 실패

이로써 공개 API의 사용자 경험과 인증 필요 API의 보호 경계를 동시에 유지한다.

---

## 4. SDK 소셜 로그인 흐름 유지

프론트 SDK 로그인 방식은 기존처럼 다음 요청으로 동작한다.

```json
{
  "provider": "kakao",
  "accessToken": "SDK에서 받은 토큰",
  "deviceNumber": "기기 식별값"
}
```

보안 필터 변경 후에도 소셜 로그인 API는 인증 없이 접근 가능하며, 잘못된 기존 JWT 헤더가 붙어 있어도 익명 요청으로 컨트롤러까지 도달하도록 검증했다.

---

## 5. 민감 토큰 로그 제거

다음 정보는 더 이상 평문으로 로그에 남기지 않는다.

- OAuth access token
- JWT access token
- JWT refresh token
- refresh token 재발급 값

대신 provider, token 제공 여부, JWT UUID 수준의 운영상 필요한 정보만 남긴다.

또한 `ReqSocialLoginDto.toString()`에서도 access token 원문을 출력하지 않도록 변경했다.
